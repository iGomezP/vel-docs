## Sprint 1 Retrospective

A Sprint 1 Retrospective was also created.

The retrospective identified several practices worth preserving:

- Deliver functionality through vertical slices.
- Allow tests to influence implementation design.
- Validate HTTP behavior independently from application-level tests.
- Introduce infrastructure only when justified by requirements.
- Keep documentation close to implementation.
- Preserve incremental Git history as engineering evidence.

The retrospective also identified improvement opportunities.

### Cross-Platform Line Endings

VEL Workbench is now edited from both Fedora and Windows.

Git produced LF/CRLF conversion warnings while Bruno files were edited from Windows.

A repository-level `.gitattributes` policy should be evaluated so line-ending behavior becomes explicit and reproducible.

### API Test Data

Bruno currently generates unique Project records during successful API test execution.

This keeps the suite repeatable, but test records remain in the development database.

No cleanup infrastructure will be introduced yet. The need will be reevaluated as the suite grows.

### Work Item Dependencies

Sprint 1 demonstrated that implementation order can change when a dependency becomes clearer during development.

Future sprint planning should make dependencies and preferred delivery order more visible.

## SSH Development Workflow

The Fedora GitHub SSH workflow was also improved.

The dedicated VEL GitHub SSH key is explicitly configured through SSH configuration, while `keychain` is used to reuse the SSH agent between shell sessions.

The shell initialization was adjusted to avoid interactive key initialization interfering with the Powerlevel10k instant prompt.

No private keys, passphrases, credentials, or private network addresses are stored in VEL repositories.
